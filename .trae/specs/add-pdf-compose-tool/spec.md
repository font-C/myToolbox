# PDF 拼接工具 Spec

## Why

用户经常需要把多张图片或多个 PDF 拼到一起来排版、打印或导出为一份完整文档。目前工具箱只有「PDF 裁剪」和「口算练习」两个工具，缺少一个集**多来源拼接、自由排版、直接打印、完整导出、覆盖标注**于一体的 PDF 拼版工具。

## What Changes

- 新增一个名为「PDF 拼接」的工具，在启动台注册网格中展示（可通过点击打开）。
- 支持**多张图片**与**多个 PDF** 混合导入并自由排版：
  - 每个导入资源生成若干「元素」（Element）：图片 → 1 个元素；多页 PDF → 每页 1 个元素。
  - 默认每个元素单独占一页（输出页）。
  - 元素可**拖动改变位置**、**拖动角点改变大小**、**跨页拖拽移动到其它输出页**。
- 每个输出页独立，支持**添加/删除/排序输出页**，页尺寸可配置（默认 A4）。
- 支持在选定页面上做**覆盖标注**：
  - **遮盖（白底黑字）**：绘制不透明白色矩形覆盖原文，可叠加黑色文字。
  - **马赛克**：对指定区域做块状模糊打码。
  - 标注随导出/打印一起输出。
- 支持**直接打印**（复用现有 `print_pdf` 原生打印链路）与**完整导出**（复用 `save_bytes` 保存为一份合并后的 PDF）。
- 全部纯本地处理，不产生网络上传。

## Impact

- 新增能力：
  - `pdf-compose`：多来源 PDF/图片拼版工具（主视图、元素排版、输出页、覆盖标注、导出与打印）。
- 复用现有代码：
  - `save_bytes` / `print_pdf` Tauri 命令（现有 `src-tauri/src/lib.rs`，无需改动 Rust）。
  - `pdf-lib`、`pdfjs-dist` 依赖（已在 `package.json`）。
  - 组件与容器模式：`App.vue`、`HomePage.vue`、`src/tools/registry.js` 工具注册、`src/stores/*` Pinia 模式、`src/composables/*` 组合式函数模式、`src/utils/cropMath.js` 的归一化坐标与 resize 辅助函数。
- 受影响代码：
  - `src/tools/registry.js`：追加一项注册。
  - `src/views/`：新增 `PdfCompose.vue`。
  - `src/stores/`：新增 `compose.js`。
  - `src/composables/`：新增 `useComposeExport.js`。
  - `src/components/`：新增拼版相关组件。
  - `src/utils/`：新增 `composeMath.js`。
  - `src/constants/pdf.js`：追加拼版相关常量。
- 与原 `pdf` 裁剪工具（`stores/pdf.js`）相互独立，不共享状态，互不影响。

## 术语约定

- 本文件全部矩形坐标采用**归一化坐标**（0~1，左上角为原点），与 `cropMath.js` 一致，避免窗口尺寸变化导致失真。
- **元素（Element）**：一次导入产生的可排版内容块。
- **输出页（Page）**：拼接结果中的一个独立页面，容纳若干元素与标注。
- **标注（Annotation）**：覆盖在输出页上的遮盖/马赛克/文字对象。

## ADDED Requirements

### Requirement: 多来源资源导入

系统 SHALL 允许同时导入多张图片（PNG/JPG）与多个 PDF 文件。

#### Scenario: 导入图片与 PDF
- **WHEN** 用户选择若干图片文件与若干 PDF 文件
- **THEN** 每个图片生成 1 个元素，每个 PDF 的每一页各生成 1 个元素，全部元素按导入顺序进入一个新建的拼版工程

#### Scenario: 默认逐页放置
- **WHEN** 导入完成后初始化排版
- **THEN** 默认每个元素单独占一个输出页，元素按页面等比缩放到约占满单页；输出页数量等于元素总数

### Requirement: 元素排版

系统 SHALL 允许用户在同一输出页内移动与缩放元素，并把元素移动到其它输出页。

#### Scenario: 拖动改变位置
- **WHEN** 用户在某个输出页上拖动某一元素
- **THEN** 该元素位置随指针变化，松手后固定在当前坐标（限定在页面范围内）

#### Scenario: 拖动角点改变大小
- **WHEN** 用户拖动元素边角/边中控点（8 个方向之一）
- **THEN** 元素宽高随之变化，且边界被限制在页面范围内

#### Scenario: 跨页拖拽移动到其它输出页
- **WHEN** 用户把某个元素拖出并悬停在另一输出页的放置区
- **THEN** 该元素被添加到目标输出页并从原页移除；若目标输出页不存在则新建一页

#### Scenario: 元素删除
- **WHEN** 用户选中某元素并执行删除
- **THEN** 该元素及其排版信息被移除，不影响其它元素

### Requirement: 输出页管理

系统 SHALL 允许用户新增、删除、排序输出页，并配置单页尺寸。

#### Scenario: 管理输出页
- **WHEN** 用户新增/删除/调整顺序或修改页尺寸
- **THEN** 输出页列表即时更新，页内元素坐标按新的页尺寸重新换算显示（归一化存储保持不变）

### Requirement: 覆盖标注（遮盖/马赛克/文字）

系统 SHALL 允许用户在选定输出页上绘制遮盖、马赛克与文字标注，并将其纳入导出与打印结果。

#### Scenario: 白底遮盖并加黑字
- **WHEN** 用户在页面上框选一个矩形区域选择「遮盖」
- **THEN** 生成一个不透明白色矩形覆盖该区域；允许在该矩形内输入并显示用于“白底黑字”的黑色文字

#### Scenario: 马赛克
- **WHEN** 用户在页面上框选一个矩形区域选择「马赛克」
- **THEN** 生成一个马赛克打码标注，导出时该区域呈现块状模糊效果

#### Scenario: 标注删除
- **WHEN** 用户选中某一标注并执行删除
- **THEN** 该标注被移除，其余内容不变

#### Scenario: 含马赛克的页面导出为位图
- **WHEN** 某输出页包含马赛克标注且用户执行导出/打印
- **THEN** 该页以整页栅格位图形式输出以保证马赛克正确生效；不含马赛克的页保持矢量输出

### Requirement: 直接打印与完整导出

系统 SHALL 支持把拼版结果一键打印，或导出为一份合并后的 PDF 文件保存到本地。

#### Scenario: 直接打印
- **WHEN** 用户在拼版工程就绪后点击「打印」
- **THEN** 按输出页顺序、页尺寸、元素排版与标注内容生成 PDF 字节，并调用现有原生打印链路（Tauri `print_pdf`；浏览器走 `window.print` 兜底）

#### Scenario: 完整导出
- **WHEN** 用户在拼版工程就绪后点击「导出」
- **THEN** 生成合并后的 PDF 字节，经现有 `save_bytes`（Tauri 系统保存对话框）或浏览器下载保存为本地文件；并提示成功或失败

#### Scenario: 空工程保护
- **WHEN** 用户尚未导入任何元素却触发打印/导出
- **THEN** 操作被禁用并给出提示，不生成空文档

## Requirements 非目标（Out of Scope）

- 不修改现有 PDF 裁剪工具（`CropTool` / `stores/pdf`）的任何行为。
- 不做 PDF 编辑（增删改原始页内文字/矢量内容），仅做「拼接 + 覆盖标注」。
- 首页 admin 无关。
