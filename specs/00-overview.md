# 插件架构总览 · 架构与安全模型

> 本文档说明 MyToolbox 插件体系的运行形态、信任边界与安全模型。

## 一、运行形态

```
┌─ 主窗口（壳子，label: main）────────────────────┐
│  启动台        商店        插件管理        设置  │
│  （读 plugin_list；点击工具 → 请求打开插件窗口）  │
└──────────────┬──────────────────────────────────┘
               │ plugin_open(id)
               ▼
┌─ 插件窗口（label: plugin-<id>，独立原生窗口）────┐
│  内容：plugin://<id>/index.html（自定义协议）    │
│  自包含前端应用（Vue/任意，依赖随包自带）        │
└──────────────────────────────────────────────────┘
```

- 主窗口是**纯壳**：启动台网格、商店客户端、插件管理、设置。插件全部打开在独立窗口，
  多个插件窗口可并存，关窗即退出插件。
- 插件内容通过 `plugin://` 自定义协议从磁盘目录（appData/plugins/\<id\>/ 或开发目录）提供：
  - Windows 下等价地址为 `http://plugin.localhost/<id>/...`（WebView2 的机制）
  - 协议处理器负责 MIME、路径穿越防护与页面 CSP

## 二、三层安全模型

### 1. 窗口级隔离

每个插件一个独立 webview：JS 上下文、`document`、`window` 完全独立。
一个插件的全局事件监听、打印层注入、`alert()` 都无法影响宿主与其它插件。

### 2. 权限代理（broker）

插件窗口**没有**任意文件读写与打印能力。它只能调用 broker 命令（`broker_*`）：

| 环节 | 规则 |
|---|---|
| 身份 | 由窗口 label（`plugin-<id>`）推导，不由参数声明——插件无法冒充他人 |
| 权限 | manifest `permissions` 未声明的能力一律拒绝 |
| 授权 | 文件路径只有三种用户动作可授权：打开对话框选中、保存对话框目标、向窗口拖入文件 |
| 生命周期 | 授权表是会话级的：窗口关闭即清空；拖拽路径由宿主在 Rust 侧记录，插件 JS 无法伪造 |

### 3. 包完整性与签名

- `.tbox` 包安装时计算 **sha256**；商店来源必须携带 **Ed25519 签名**（对 sha256 hex 签名），
  公钥编译进宿主（`plugin_installer.rs::STORE_PUBKEY_HEX`）
- 本地导入（.tbox 双击/管理页导入）允许未签名包，但 UI 明示来源并要求确认
- 商店索引（index.json）由 CI 用私钥签名后发布，详见 [04-packaging-signing.md](./04-packaging-signing.md)

## 三、内置插件

`plugins/` 下的三个工具（pdf-crop、pdf-compose、mental-math）本身完全按本规范开发，
经 `npm run build:plugins` 打包后**编译期嵌入**宿主（include_bytes!），启动时确保安装：

- 内置插件不可卸载、可停用；随宿主发版升级
- 用户从商店装了同 id 且版本更新的插件时，保留用户版本（不回退）

## 四、插件开发者的心智模型

- 你的插件是一个**普通前端应用**：Vite 构建、可以用 Vue/React/原生 JS、依赖随包自带
- 「宿主 SDK」是一个极薄的封装（`window.toolbox` 风格 API，见 [03-sdk-api.md](./03-sdk-api.md)）：
  文件对话框、已授权路径读取、保存、打印、拖拽事件、关窗
- 主题：`import '@toolbox/plugin-sdk/theme.css'` 获得与壳子一致的设计变量与 `.btn/.spinner` 等通用控件
- 不提供网络：v1 插件页 CSP 禁止任何远程请求（`connect-src` 仅限自身/数据/blob），
  需要联网数据处理能力的插件请等待网络权限提案（`net:fetch`）
